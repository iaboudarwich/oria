## Deferred, and why

- **Gmail/Outlook and Google/Microsoft OAuth modules stay separate.** They share
  the ingest pipelines (runEmailScan, ingestCalendarEvents) and the low-level
  sidecar helpers, but the OAuth primitives (auth URL, token exchange, refresh)
  differ enough per provider (Google vs Microsoft endpoints, Microsoft refresh
  rotation) that merging them would hurt clarity. Kept separate per the round's
  "don't force refactors that hurt clarity" guidance.
- **Microsoft token revoke.** Microsoft has no simple server-side delegated-token
  revoke endpoint, so disconnect deletes the local row (and cascades) without an
  API revoke; the user can revoke from their Microsoft account. Documented in
  the disconnect path.
- **Provider-neutral Ask citation label.** Linked-file citations read "Files"
  (not "Drive"/"OneDrive") in the meta line; the click-through link still opens
  the correct provider. Per-file "Open in OneDrive" vs "Open in Drive" is shown
  in the section list (which carries the provider).
- **Connections hub kept as separate Google + Microsoft panels** (each grouped
  by account) rather than one unified panel, to avoid a larger UI refactor of
  the mature Gmail card.

## Environment variables

- Required (set in Vercel): `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET`.
- Optional: `MICROSOFT_OAUTH_TENANT` (default `common`), `MICROSOFT_REDIRECT_URI`
  (default `https://heyoria.com/api/oauth/microsoft/callback`).
- `TOKEN_ENCRYPTION_KEY` optional (falls back to GOOGLE*/GMAIL* keys).
- The Azure app must register the redirect URI and the delegated scopes
  Mail.Read, Files.Read, Calendars.Read (plus offline_access).
