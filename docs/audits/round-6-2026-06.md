## Performance review (vs docs/perf/2026-06-baseline.md)

Static analysis only; runtime Lighthouse on the auth-gated dashboard pages
still needs a signed-in maintainer run (no session / no Chrome here), exactly as
the baseline records.

- **No new render-path regressions.** The new layout reads added this round
  (`getSeenHintKeys`, `listGmailConnections` for the sidebar health dot) were
  added INSIDE the existing `Promise.all`, so they run in parallel with the
  other layout queries, not sequentially on the render path.
- **Connections panel** added `listUserSpaces` in parallel with the existing
  per-connection fetches (`Promise.all`), no sequential await added.
- **Command palette** is a client component that fetches `/api/search` only
  after the user opens it and types; it adds nothing to first load.
- **Cross-section retrieval** pulls extra section memories only when a query is
  unscoped AND names two or more section themes, a bounded, infrequent path.
- **/privacy** changed from static (`revalidate=86400`) to per-locale dynamic
  (it now calls `getTranslations`). It carries no heavy data; the baseline had
  it at ~0.29s edge TTFB and this remains a tiny server render. Acceptable and
  intentional (the human layer must be localized).
- Public-route TTFB targets from the baseline (`/`, `/login`, `/privacy`,
  `/terms`, `/api/version` ~0.22–0.29s) are unaffected for the others.
