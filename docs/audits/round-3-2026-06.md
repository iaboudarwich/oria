## Performance verification vs baseline

`docs/perf/2026-06-baseline.md` carries placeholder runtime cells
(`_measure_`) because TTFB / TTI / LCP and API p95 can only be captured against
production (heyoria.com), not from the build environment. So this round's
verification is static:

- The section pages add a summary card and an optional intelligence view. The
  summary is computed in parallel with the existing entry fetch (no added
  serial latency). The intelligence views (Spend / Trips / Timeline) render
  only on their own `?view` tab, so the default file list is unchanged.
- The Bills "Spend" chart reuses the existing inline-SVG `ReportChartView`
  rather than adding `recharts`, so first-load JS does not grow.
- No new client component ships on the default section render path; the new
  view components are server-rendered.

Action for the maintainer: run Lighthouse on the five baseline pages plus
`/dashboard/sections/travel`, `/dashboard/sections/health`, and
`/dashboard/bills?view=spend`, and capture API p95 from Vercel, to fill the
baseline table and confirm no >10% regression.

## Smoke test (to run interactively; cannot be executed from the build env)

1. Visit each section with data: summary card shows something useful; empty
   sections show the existing empty state, not a placeholder summary.
2. Bills -> Spend tab: monthly bar chart + category breakdown render under 1s.
3. Travel -> Trips tab: flights grouped into trip cards, each linked to its
   upload. Health -> Timeline tab: chronological list with the type filter.
4. Settings -> Preferences: set short responses + Bills focus; ask Oria a
   question (answer is shorter); the Ask empty-state suggestions lead with a
   bills question. "What Oria has noticed" reflects recent activity.
5. Settings -> Preferences -> Reset Oria's understanding: the noticed panel
   clears; explicit preferences remain.

## Deferred (with reason)

- Per-user hide/show of the intelligence-view tabs: needs a `section_settings`
  column; not added this round.
- Reminder-class suppression and re-categorization learning from the profile:
  those pipelines run in background `after()` contexts that do not carry the
  acting user's profile. The personalization primitives exist; wiring them in
  needs the profile threaded into those jobs.
- Travel weather snapshot: no weather provider is configured.
- Generic-section AI paragraph: defaulted to a fast structured summary to
  protect section TTFB; the AI variant can layer on behind a 24h cache.
