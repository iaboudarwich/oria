## F1 - template name leakage audit

Searched every user-facing surface for the nine real-life template names (Renter,
Homeowner, Parent, Freelancer, Frequent Traveler, Teacher, Caregiver, Investor,
Custom) and the four abstract category names (Personal, Business, Family Office,
Custom).

| Surface                         | Finding                                                                | Action                                                                                                                                                                                                    |
| ------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `messages/*.json`               | No template proper-nouns                                               | none needed                                                                                                                                                                                               |
| `lib/onboarding/templates.ts`   | Catalog `displayName`/`description`                                    | internal selection metadata; never rendered (verified by grep)                                                                                                                                            |
| `app/onboarding/preview`        | "Here's what I'll build" framing                                       | reframed to "Here's what I built for you / Tweak anything... or build it as is", single "Looks good, build it" confirm                                                                                    |
| `app/dashboard/work/spaces/new` | **Leak**: picker showed Personal / Business / Family Office / Investor | relabeled to neutral content descriptors ("Operations and finances", "Investments and portfolio", "Properties and estate"); seed key kept internal; page localized; personal dropped from the work picker |
| `lib/ai/suggested-questions.ts` | Static fallback bucketed by template                                   | returns questions, never a template name; simplified to investor + area                                                                                                                                   |
| Settings / dashboard headers    | Spaces shown by user name + accent                                     | no change needed                                                                                                                                                                                          |

Result: zero template proper-nouns reach the UI.

## F2 - premium generation animation

`components/onboarding/build-animation.tsx`: a ghost dashboard skeleton, section
names settling in one by one, an accent wash, and a four-phase narrative. No
framer-motion in deps, so it is built on CSS transitions + Tailwind + timed React
state. Restrained motion (opacity, <=16px slides, a color wash). Reduced-motion is
handled in CSS (`motion-reduce:hidden` on the skeleton) so those users get the
narrative line alone, still advancing.

Applied to the onboarding preview build (~7s) and the reshape engine's plan
execution (~4.5s). The duplicated completion-gating across the two clients was
extracted into `useBuildGate` (one place: reset / signalAnim / signalExec /
ready).

## F3 - Gemini vision parity

`lib/ai-providers/gemini.ts` maps image content blocks to `inlineData` parts
instead of dropping them. All three tiers are vision-capable (gemini-1.5-pro,
gemini-1.5-flash, gemini-2.0-flash-thinking-exp; the fast 1.5-flash tier has
smaller image limits). This resolves the Round 12 "Gemini vision" deferral -
Anthropic, OpenAI, and Gemini are now all true multimodal providers.

## F4 - setup-intent on image queries

Removed the `images.length === 0` skip in `app/api/ask/route.ts`; the setup-intent
classifier now reads the text of every query. When a setup change is detected on
an image query, Oria reroutes to the reshape preview but shows an acknowledgment
and the dismiss action becomes "just answer my question with the image", which
re-runs the Ask with the image preserved (the thumbnails stay on the turn). New
audit events: `ask_setup_intent_with_image_detected` / `_rejected`.

## F5 - abstract template_key retirement

**Schema reality first** (Round 12 lesson): queried production before writing.
`organizations.template_key` (added in 0033) held only `custom` (1), `personal`
(1), and NULL (6); no business/family_office/investor rows. The constraint was
the abstract `IN (...)` set.

`0065_template_key_refactor.sql`: backfills `personal`/`business`/`family_office`
to `custom` (auditing each row as `setup_template_retired`), drops the old
constraint, and adds a new CHECK allowing the real-life onboarding ids plus
`custom` (NULL still passes and is untouched).

Consumers are now template-agnostic:

- `space-theme.ts`: dropped the per-category accent map; the accent (set at
  creation) drives the theme, with an area-based fallback.
- `things-label.ts`: keeps "Assets" only for the preserved `investor` template.
- `suggested-questions.ts`: investor bucket + area; the family_office bucket was
  removed as dead.
- `resolveStoredTemplateKey`: stamps only `investor` or `custom`, so a retired
  seed still seeds its sections but never lands an abstract value on the row.
- `Organization.template_key` type narrowed to the new set.

**Deviations, called out honestly:**

- The constraint uses the catalog id `traveler` (its display name is "Frequent
  Traveler"); the spec's example SQL wrote `frequent-traveler`. The catalog id is
  the value the code would ever stamp, so the constraint follows the code.
- The in-app seed catalog (`lib/data/workspace-templates.ts`) keeps its internal
  seed-set keys (personal/business/family_office) as plumbing, decoupled from the
  stored vocabulary, rather than deleting the definitions. Deleting them would
  remove the only in-app section-seeding capability (a behavior regression the
  standing rules forbid) with no replacement. The abstract values are retired
  from the **stored** data model (column constraint, theming, labels, stamped
  key), which is F5's goal; they survive only as internal seed identifiers that
  collapse to `custom` when stored.

## Performance

Baseline: `docs/perf/2026-06-baseline.md`. No render-path regressions.

- **Build animation is non-blocking.** It runs entirely client-side on React
  timers + CSS. The real work (generateOnboardingPlan / executeOnboardingPlan /
  reshapeExecutePatch) runs in parallel via server actions; the client navigates
  only once both the choreography and the real work settle (`useBuildGate`). The
  animation adds no server cost and cannot delay generation.
- **Onboarding machine-time budget (target < 90s).** The automated legs:
  generation (reasoning tier, ~20-40s) + build animation (~7s, overlapping the
  ~1-3s execution) ~= 30-50s of machine time. The demo (~30s, auto-advancing,
  skippable) and the conversation are user-paced and not counted against the
  machine budget. Start-to-reveal for the median user stays within target for the
  non-interactive portion; the conversation length is the user's to set.
- **Gemini vision latency.** Not independently measured (no Gemini BYO key in this
  environment). The image payload is the same base64 already prepared by
  `lib/ai/ask-images.ts` (<=10MB/image, <=5 images, HEIC pre-converted), passed as
  `inlineData`; gemini-1.5-flash (fast tier) is the typical path. No Oria-side
  overhead is added beyond the part mapping.
