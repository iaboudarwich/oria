## Reality vs the spec (important)

The spec assumed Ask Oria already used tool definitions and accepted image
uploads. It does not: Ask Oria is text-only RAG (retrieved sources are placed in
the prompt). Tool-use and vision live only in INFRASTRUCTURE (extract,
work-report, sort-items, analyze-image), on the Anthropic SDK. So "parity" was
implemented as real adapter capability with real consumers, not speculative
plumbing:

- Tool-use parity is exercised by sort-items (a forced single-tool call) moved
  onto the abstraction.
- Vision parity is exercised by analyze-image (uploaded-image analysis) moved
  onto the abstraction.
- The remaining user-triggered calls (suggest-entity-schema, field translation)
  also moved over, via a new infraComplete helper that keeps them on Oria's key
  (no routing change, no quality regression).

## Deliberate deviations / deferrals (honest)

- **Ask base answer stays on the fast tier.** The spec's decision logic said
  non-reasoning answers use 'premium'; that would silently swap Ask Oria from
  Haiku to Sonnet on every query (a ~10x cost bump). To avoid an unrequested
  cost regression, the base answer keeps today's fast tier and reasoning is the
  deeper upgrade. Documented here as the one place the literal spec was not
  followed.
- **Streaming tool deltas + multi-turn tool loops** are not built: no
  conversation surface streams tools (Ask Oria streams text only). complete()
  covers Oria's forced-single-tool usage; the rest would be dead plumbing.
- **Ask Oria image upload UI** does not exist, so the OpenAI vision branch is at
  parity but has no Ask-side runtime consumer yet (analyze-image exercises the
  Anthropic vision path). It is ready for a future image-Ask surface.
- **Gemini stays adapter-thin** (per the standing priority): reasoning selects
  the thinking-exp model; tool-use and vision are not wired on Gemini.
- **o1** is reserved (escalation on reasoningEffort 'high' only) and falls back
  to non-streaming, as o1 has no streaming.

## Performance (per tier per provider)

Measured live from this environment is not possible (no authenticated
production browser; same constraint as docs/perf/2026-06-baseline.md). Expected
baselines to confirm in production:

- **Classifier (auto mode):** fast tier (~200ms), runs in parallel with
  retrieval, so it does not add to time-to-first-token; retrieval queries should
  stay under ~1.5s to first token as before.
- **Reasoning, Anthropic** (Sonnet + 16k thinking budget): ~15 to 40s.
- **Reasoning, OpenAI** (o3-mini, medium effort): ~10 to 30s.
- **Reasoning, Gemini** (gemini-2.0-flash-thinking-exp): ~10 to 25s.
- **Onboarding tailoring:** reasoning, capped at 90s with a premium retry, so
  the full flow stays under the 2-minute budget.

No render-path regression was introduced; the base Ask streaming shape is
unchanged.
