# Round 8 audit, June 2026

Cleanup pass over the files touched across F1 through F6 (Google Drive file
linking + Google Calendar sync), plus a performance review and a smoke-test
checklist. Verdicts: kept / removed / consolidated / fixed / deferred.

## What this round shipped

- F1: `cloud_connections` model (migration 0056) + a generalized Google OAuth
  flow (`/api/oauth/google/connect|callback`) adding calendar.readonly and
  drive.file on top of the existing Gmail app, with incremental auth and a
  backward-compatible `GOOGLE_TOKEN_ENCRYPTION_KEY`.
- F2: Drive file linking via the Google Picker (migration 0057 `cloud_files`),
  references-only storage, background indexing (summary + embedding), and
  hourly folder sync.
- F3: fetch-on-demand reading (sidecar `/cloud/drive/fetch`, 5-minute Redis
  cache, never persisted) + Ask Oria retrieval over linked files (migration
  0058 `match_cloud_files`).
- F4: Calendar sync (migration 0059 `calendar_events`), heuristic + batched
  Haiku categorization, section routing, hourly cron, dashboard "Coming up"
  strip, and per-section event lists.
- F5: multi-service Google connections hub (grouped by account) + onboarding
  link step going live for Calendar/Drive (Docs/Sheets/Slides gated on Drive).
- F6: this audit + shared-helper consolidation.

## Architectural decisions honored

- **drive.file, not drive.readonly.** Only files the user explicitly picks are
  reachable. Non-restricted scope, no restricted-scope security audit.
- **Files linked, never stored.** `cloud_files` holds the reference + metadata
  + an AI summary only. Content is fetched on demand and cached in Redis for 5
  minutes (keyed on provider id + modified time), never written to the DB.
- **Parallel storage model.** Gmail stays in `email_connections`, untouched;
  Calendar/Drive live in the new `cloud_connections`. Consolidation of the two
  is deliberately deferred (the round's stated decision).

## Deferred, and why

- **Gmail/cloud OAuth + token-refresh consolidation.** `gmail/oauth.ts`
  (`refreshAccessToken`) and `google/oauth.ts` (`refreshGoogleAccessToken`) are
  near-identical, as are the two connection data layers. The round's
  architecture decision says to keep them parallel and not consolidate now, so
  only the genuinely-shared sidecar HMAC helper was extracted. A future round
  can merge the OAuth primitives.
- **Calendar fixed-routing to multiple orgs.** `calendar_events` is unique per
  (user, connection, event), so an event routes to a single org (first fixed
  target, or Personal in auto), unlike Gmail's multi-target copy. Multi-org
  calendar fan-out would need a different key and is deferred.
- **Unified single-card connections view.** The Google services hub is grouped
  by account but presented alongside the mature Gmail card rather than merged
  into one card per account, to avoid regressing Gmail's filters/scan/routing
  controls. Deferred to a UI consolidation pass.
- **Per-event audit rows.** The spec suggested auditing each synced event; that
  would flood the log, so one `cloud.calendar_synced` row per sync carries the
  count instead (matching `email.scan_completed`).

  `GMAIL_TOKEN_ENCRYPTION_KEY`).
- `GOOGLE_PICKER_API_KEY` and `GOOGLE_PICKER_APP_ID` (required for the Drive
  Picker to open; the link button reports "Picker unavailable" without them).

  scopes, and the redirect URI `/api/oauth/google/callback` must be registered.

## Smoke-test checklist (after sidecar redeploy + env + migrations)

1. Settings -> Connections: connect Google Drive; OAuth shows the drive.file
   consent; a row appears under the account in the Google services hub.
2. Connect Google Calendar on the same account via incremental auth; the first
   sync runs in the background and events appear.
3. In a section, "Link Google files" opens the Picker; pick a Doc; it appears
   with metadata, then a summary after indexing. "View" loads content in a
   modal; "Open in Drive" links out.
4. Ask Oria a question answered by a linked file; the answer cites it with its
   Drive link. Delete the file in Drive; next view shows the inaccessible state.
5. A "Flight to LAX" event lands in Travel, a "Dentist" event in Health; the
   dashboard "Coming up" strip shows the next day or two and is dismissible.
6. Disconnect one service; the others on the account survive; the sidebar dot
   reflects overall health.
7. Onboarding link step shows Calendar + Drive as live; connecting Drive lights
   up Docs/Sheets/Slides. Locale switch (ar/fr/es) shows translated copy.
